\subsection{Electrical schematic} \label{sec:hardware_electrical_schematic}

Using the components described in the previous chapter, an electrical schematic is created. This schematic captures the logical behavior of the architecture and the software implementation. At this point, the number of modules of the hardware implementation is decided. In total, four different electrical schematics are developed. The full schematics are too large to include at this point, therefore they can be found in \appref{app:schematic_alu} - \appref{app:schematic_register}. To design both the electrical schematics and \acp{pcb}, the software distribution ``KiCAD'' 9.0 is used.

\subsubsection{Common Circuits}

Throughout the design of all schematics, a set of circuits which are used in multiple places emerges. These circuits are small, reusable building blocks for common tasks. One such circuit is the \ac{io} stage. It is used in all places where a signal is routed to an external connector of the schematic. This is necessary in order to amplify the signal, outputting a voltage as close to the \texttt{HIGH} voltage level as possible. It also includes an \ac{led} for visualisation to the user. It consists of one N-channel and one P-channel \ac{mosfet}. This is needed in order to not invert the input signal. It is also biased using a single \SI{100}{\kilo\ohm} resistor.

    \centering

    \caption[IO stage circuit]{1 Bit Input/Output stage, input signal on the left, output on the right}
    \label{fig:hardware_schematic_io_stage}
\end{figure}

Another commonly used element is the decoupling capacitor. When switching, each logic gate \ac{ic} requires some amount of charge to change its output voltage level according to its logic function. However, the capacitance of the copper traces of a \ac{pcb} may not contain enough charge to fully saturate all components of large circuits. If this is the case, then the voltage of the net drops locally, referred to as a brown-out. This can lead to unpredictable behavior, since some or all of the logic \acp{ic} may stop behaving as intended at lower voltages. The likelihood of this occuring increases with the frequency of state change, which in this work, is the clock frequency of the \ac{cpu}. For this reason, additional capacitance is added. Each \ac{ic} receives a dedicated buffer capacitor near its supply pin, increasing the capacitance of the supply net locally. For these capacitors, \SI{100}{\nano\farad} of capacitance is recommended by manufacturers \cite{ti_sn74hc00,microchip_atmega2560}. In addition to this, each schematic module has a set of larger capacitors to provide more global capacitance. For this purpose, \SI{22}{\micro\farad} electrolytic capacitors are used as recommended by the manufacturer of the power \ac{ic} used\cite{tracopower_tsr3}.


\subsubsection{Modules}

The logical design has been partitioned into functional modules in \autoref{sec:architecture_modularisation}. However, these modules differ significantly in size, complexity and number of components needed. For example, while the memories take up a significant amount of space in the module diagrams, they physically only require a single \ac{ic} each. Therefore, to minimize manufacturing cost, a new set of electrical modules is chosen by merging related logical modules into fewer electrical schematics.

\paragraph*{Arithmetic logic unit}

The arithmetic logic unit represents both a logical and electrical module. It consists of 508 \texttt{NAND} logic gates, which is $24.9\%$ of the total number of gates. This number of components warrants a distinct schematic and \ac{pcb}. The initial design, for which a prototype \ac{pcb} was created and tested, has split up this module further. It consisted of the same three computation modules present in the logical design, as well as a larger board which served as a connecting piece and provided the external connector. However, through doing so, the \acp{pcb} were found to be unnecessarily large and therefore expensive. For this reason, the second revision combined all four boards into one.

\paragraph*{Register \& Register File}

The register file contains $\approx 51\%$ of all \texttt{NAND} gates, which was deemed too large for a single schematic and \ac{pcb}. Since all of the registers contained within it are identical and can be reused, a schematic is created for an individual 8 bit register. This can then be reused for both the register file and program counter. A separate schematic contains the remaining 401 \texttt{NAND} gates, representing $\approx 19.6\%$ of all gates. This schematic contains all multiplexing and control logic needed by the register file. This ``register fabric'' board contains seven connectors for interfacing the smaller individual registers.

\paragraph*{Input/Output}

All other modules and components are contained within the last schematic, which is referred to as the \ac{io}-board. This schematic contains all other logic elements. It implements 488 of the 2041 total \texttt{NAND} gates of the logical design ($\approx 23.9\%$). It subsumes the following modules:

\begin{itemize}
    \item Program counter
    \item Memories
    \item User \& external interface
\end{itemize}

\subsubsection{Translating logical to electrical circuits}

The design of all schematics follows the same process. The first step in this process is to define and place the symbol for the external connector of the schematic. By doing so, all input and output signals to the entire circuit are defined. Checking which ones are already connected gives an indication of the overall progress of the design.
\\

Following this, all boolean logic circuits are directly translated into their electrical counterparts. All components in the schematic are placed identically to the logic simulation, whereever possible. All connections between gates are also copied directly. In addition to the boolean circuit, each logic gate is also connected to a positive and ground plane in order to supply power. Some components such as multiplexers are built from \texttt{NAND} gates only in the software simulation and are replaced by corresponding \acp{ic} in this step.
\\

While in the logic simulation, a single output can drive an arbitrary number of inputs, this is not the case with real components where any one output pin can only drive a limited number of inputs. This number is referred to as the ``fan-out'' of that pin or device. With the ``SN74HC'' family of \acp{ic}, the manufacturer guarantees a fan-out of 10 \cite{ti_sn74hc00}. However, in the logical circuit, an output signal of some \texttt{NAND} logic circuit drives more than this. Therefore, all such signals must be routed through an \ac{io}-stage, which significantly increases the fan-out. Likewise, all signals that come into or go out of the circuit go through such a stage in order to bias their values to \texttt{LOW} and clean up attenuated signals.
\\

After the digital logic circuits are translated, additional components are added:

\begin{itemize}
    \item \textbf{Decoupling capacitors} Smooth out the voltage of the power supply and ground nets
    \item \textbf{Mounting holes} Allow the \ac{pcb} to be bolted onto a surface
    \item \textbf{Power indicator \acp{led}} Turns on when board is powered
\end{itemize}

These basic components are present in all schematics. Depending on the type of circuit, more specialised components such as the arbiter microcontroller or memory interfaces are added. Their integration is explained in more detail below.

\subsubsection{Memory busses}

The abstract memory devices in the logical and software design have distinct inputs and outputs. However, the physical memory components are designed to be interfaced using a single set of data lines for both input and output. Since either the result of the \ac{alu} or a value read from the working memory can be read into a register, they must at some point be electrically connected. Using a multiplexer is not possible because the same data lines of the memory are used to write the \ac{alu} result to that memory. Therefore, a data bus is necessary. This bus, in combination with the address bus used to index the memory, is made available to external modules with a dedicated connector. This enables memory mapped \ac{io} as explained in \autoref{sec:fundamentals_isa_memory_model}. \\

Since the output of the \ac{alu} does not support tri-state logic, an 8 bit buffer \ac{ic} is introduced. This buffer chip provides a dedicated ``Chip enable'' signal, which can disconnect its outputs from the bus. The memory \ac{ic} already has this pin and is therefore directly compatible. At the time of writing, this internal memory is the only bus member, providing \SI{32}{\kibi\byte} of working memory. All other internal busses are point-to-point connections and therefore do not require tri-state logic.
\\

All \acp{rom} are used as lookup-tables and are therefore operated in their read-only mode. However, they must be accessible for \ac{icp} and therefore also written to. When doing so multiple producers need to access their data lines. Therefore, the data and address lines of each \ac{rom} are multiplexed using bidirectional multiplexers. This way, the \ac{icp} circuit can switch between the regular operation of the \ac{rom} and the programming mode. This way, it can program each \ac{rom} chip individually. However, since each \ac{ic} has 16 lines for addressing, 8 lines for data and 2 lines to control whether to read or write, this requires a lot of pins on the arbiter \ac{mcu}. With six \ac{rom} chips, this results in a total of $6 \cdot (16 + 8 + 2) = 156$ pins. To reduce this number, another memory and address bus is introduced.
\\

\autoref{fig:hardware_schematic_memory_bus_multiplexing} shows how the bus access is managed for each \ac{rom} chip. Each chip is connected to two bidirectional buffers, which serve as the tri-state interface to the memory bus. Each buffer can be enabled or disabled by a control signal. The control signal between the two buffers of each individual \ac{rom} chip is shared but inverted for one of the two. This guarantees that for one \ac{rom}, only one of the two buffers is active at any one time. By default, i.e when the control signal is off, each set of buffers by default passes the signals from the \ac{rom} to the relevant connection within the \ac{cpu}. If the control signal is set to \texttt{HIGH}, the group of buffers instead connects the \ac{rom} chip to the shared data line, allowing the arbiter to access it. To guarantee that only one of the \acp{rom} is connected to the data line at a time, a decoder is used. It outputs \texttt{LOW} on all lines except for the $n-th$ line, where $n$ is the binary number applied to its $log_2(n)$ inputs. Output 0 is not connected to a \ac{rom} access group. This allows normal operation without the arbiter interfering, where all \acp{rom} output their contents to the relevant circuits within the device. In \autoref{fig:hardware_schematic_memory_bus_multiplexing}, only a single data line is shown. However, for all \acp{rom}, all 16 address lines, 8 data lines and the ``read'' and ``write'' pin of each chip are multiplexed in this way.
\\

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{images/drawio/memory_multiplexing.png}
    \caption[Electrical bus with bidirectional buffers]{Memory bus implemented with bidirectional buffers and a decoder with an arbitrary number of \acp{rom}. Dotted lines indicate control signals, solid lines indicate data signals.}
    \label{fig:hardware_schematic_memory_bus_multiplexing}
\end{figure}

This reduces the number of pins required for programming all 6 \acp{rom} from $156$ to only $26$. However, it requires programming to be done sequentially as only one chip can be accessed at a time. According to the datasheet, a full programming cycle for one chip takes \SI{2}{\second}. Therefore, when a installing a new program on the device, this takes up to \SI{8}{\second}, which is deemed fast enough.

\subsubsection{Arbiter}

The ``ATMega2560'' microcontroller that is used as an arbiter for generating the clock signal and implementing the \ac{hmi} and memory programming interface. It is integrated into the schematic according to the recommended configuration in the reference manual provided by the manufacturer. It has an external \SI{16}{\mega\hertz} crystal for precise timing, as well as an \ac{icsp} connector for installing software. It also has a set of 6 buttons connected to it. These buttons are debounced as described in \autoref{sec:hardware_hmi}. The output of the debounced buttons are connected to interrupt-capable pins of the arbiter \ac{mcu}. This way, input is processed in an event-driven manner, saving processing time by avoiding polling. Assigning the functionality to each button is done in the arbiters software. The following actions are planned:

\begin{itemize}
    \item \textbf{Decrease clock} Decrease the frequency of the clock signal
    \item \textbf{Increase clock} Increase the frequency of the clock signal
    \item \textbf{Toggle clock} Enable or disable clock signal generation
    \item \textbf{Step} When clock is disabled, execute a single instruction cycle
    \item \textbf{Halt/Continue} Halt execution, or, when already halted, continue at next instruction
    \item \textbf{Reset} Clear all registers and resume execution at address 0
\end{itemize}
