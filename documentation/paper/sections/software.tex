\section{Software}

Before creating a hardware implementation of the logical design, software is used to emulate the desired behavior for system validation. If the behavior of the software system adheres to the \ac{isa}, it can be used as a basis for designing hardware. Depending on the implementation level of the software system, the effort for transitioning to an electrical design is minimal. For example, if simulation software is used to create a system on the level of individual logic gates, each gate usually has a direct electrical counterpart. The downside of this is that the simulation generally involves greater overhead than a manually written software emulator and comprehensive testing requires more effort. Therefore, in this work, two software systems are created to test the logical design. The first is a simulation on the logic gate level to have a visual representation of the digital circuit, as well as a base for hardware implementation. The second is an emulator that can be easily tested and provides entry points for comprehensive testing, debugging and tracing. Both pieces of software adhere to the \ac{isa} definition and are able to execute software written for the architecture. By having two such systems, the probability of a mistake in implementation is reduced.

As the architecture is derived within this work, there is no existing software tooling. Without such tools, programmers must create their programs by hand by writing and encoding binary files in the expected instruction encoding. This is cumbersome, error prone and inefficient. To give programmers an efficient way of implementing software for the system, a compiler is needed. Such a tool transforms a sequence of human-readable code into the native instruction format. Since the complexity and size of programs for the \ac{isa} designed for this project is rather limited by the available memories, implementing a compiler for a high-level language is not worth the time investment. Therefore, a simple assembler is implemented.
